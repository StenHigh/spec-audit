# Контроль typed SDK: заказы и котировки

Синтетическая спецификация для приёмки профиля laravel. Не связана с бизнес-проектом.

### REQ-LARA-001 — Активные заказы

Условие: сервис запрашивает активные заказы.

Требование: сервис должен выбирать заказы через область `active` модели `Order`, а не фильтровать в памяти.

Проверка: тест проверяет, что неактивный заказ не попадает в выборку.

### REQ-LARA-002 — Котировка через контракт

Условие: сервису нужна котировка суммы.

Требование: сервис должен получать котировку через контракт `QuoteContract`, привязка которого задаётся провайдером.

Проверка: тест подставляет реализацию контракта и проверяет удвоенную сумму.
