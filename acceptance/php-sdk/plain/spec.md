# Контроль typed SDK: хранилище значений

Синтетическая спецификация для приёмки SA-031…034. Не связана с бизнес-проектом.

### REQ-DEMO-001 — Сохранение в файловое хранилище

Условие: сервис получает пару ключ/значение для файлового хранилища.

Требование: сервис должен сохранить значение через `FileStore::save`, а не через одноимённый метод другого хранилища.

Проверка: тест вызывает сохранение и проверяет сохранённое значение, а не только факт вызова.

### REQ-DEMO-002 — Уведомление через контракт

Условие: значение сохранено.

Требование: сервис должен уведомить получателя через контракт `Notifier`, реализация которого выбирается вне сервиса.

Проверка: тест подставляет реализацию контракта и проверяет переданное сообщение.

### REQ-DEMO-003 — Поиск пользователя

Условие: сервису передан идентификатор пользователя.

Требование: сервис должен искать пользователя через репозиторий, унаследовавший поиск от базового репозитория.

Проверка: тест проверяет возвращённое имя пользователя для существующего и отсутствующего идентификатора.
