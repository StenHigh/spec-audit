# spec-audit

Нативный инструмент для проверки объявленных Markdown-требований по коду и утверждениям тестов. Существующая AI-сессия распределяет смысловой анализ между mapper/redteam; бинарник проверяет цитаты, ведёт состояние и строит JSON/HTML. Ключи и модельные API ему не нужны.

Первый рабочий срез, не сертификатор соответствия. Он различает дефект реализации, слабый тест, неизвестность и неоднозначную норму. Зелёный запуск не превращает эти состояния в PASS.

## Спецификации

- [Спецификация инструмента и контракт CLI](docs/tool-spec.md) — подготовлена до реализации; ISO-ориентирована, формальное соответствие ISO не заявлено.
- [Контроль извлечения из legacy Markdown](docs/legacy-extraction.md) — отдельный эксперимент до расширения CLI, без переписывания исходного ТЗ.
- [Отдельная спецификация применения к SMSPlace](docs/smsplace-adoption.md) — пока read-only, без миграции /TZ и отключения trace.
- [Skill-лаунчер](skills/spec-audit/SKILL.md) и [протокол независимой роли](skills/spec-audit/references/protocol.txt) — не устанавливаются автоматически.

## Сборка и проверки

Разработка: Go 1.27.0; поддерживаемые ОС — macOS/Linux. Из этого репозитория:

```bash
go test ./tool
go vet ./tool
CGO_ENABLED=0 go build -o bin/spec-audit ./tool
```

Готовому бинарнику для init/index/prepare/tasks/submit/retry/status/report не нужны Go, Node, Python, PHP или доступ к модели. `test` требует runtime проверяемого проекта: Go либо PHP в проверенном Docker Compose container. PHP на хосте не запускается. Тесты инструмента используют синтетические данные; Docker-протокол дополнительно проверяется подставным процессом, без доступа к SMSPlace.

## Первый запуск

```bash
./bin/spec-audit init /absolute/path/audit.yaml
# Отредактируйте пути по контракту спецификации.
./bin/spec-audit index /absolute/path/audit.yaml
./bin/spec-audit prepare /absolute/path/audit.yaml first
./bin/spec-audit tasks /absolute/path/audit.yaml first
./bin/spec-audit report /absolute/path/audit.yaml first
```

init создаёт только отсутствующий YAML, не каталоги исходников. Относительные project_root/reports_dir считаются от CONFIG. Каждый ответ роли отправляется через `submit CONFIG RUN_ID TASK_ID RESULT_PATH`; retry сохраняет предыдущую попытку. Все команды возвращают JSON, LOG_LEVEL управляет диагностикой stderr. Успешная команда `test` возвращает receipt: проверяйте его `state`, а не только exit самого CLI.

Без AI можно индексировать, просматривать задания/отчёты и явно запускать разрешённые тесты. Для смыслового аудита используйте лаунчер в текущей сессии. Он не пишет AI Factory планы/CELL в проверяемый проект и не создаёт issues. Для SMSPlace даже CONFIG и reports_dir на этом этапе находятся вне бизнес-репозитория.

## Приёмка и ограничения

[Пять независимых примеров](acceptance/corpus/rules.md) и [ожидания](acceptance/expected.json) зафиксированы хэшами до новой реализации. Автоматический тест проверяет механику; отдельные свежие роли не получают gold. Отчёты реальных локальных проходов — в `.local/`.

Контроль 2026-09-15: обе роли совпали с ожидаемыми состояниями всех пяти примеров; это не статистическая оценка точности. Самоприменение нашло дефекты отчёта и PHP-запуска; исправления закреплены регрессиями, исходные выводы сохранены. Автономные команды исполнены с пустым PATH на macOS/Linux ARM64; x86_64 проверен только сборкой. SDK и PHPUnit дополнительно испытаны в отдельном read-only контейнере без сети.

Отдельный legacy-контроль: два свежих извлечения дали 12 и 11 кандидатов. Независимый reviewer, сначала составивший собственную инвентаризацию, подтвердил сохранение 14/14 контрольных обязанностей в каждом ответе, без добавленных норм. Валидатор проверил цитаты и полный учёт оценок; сырые ответы сохранены без правки в `.local/legacy-control/`. Проверены шесть синтетических случаев и реальная проза нашей спецификации. Это приёмка небольшого набора, не готовый legacy-извлекатель в CLI и не доказательство точности на других ТЗ.

- v0.1 разбирает явный профиль `REQ-...`; полнота относится к объявленным нормам. Семантическое извлечение произвольного legacy-ТЗ ещё не принято. Массовая переформатировка SMSPlace не требуется.
- Snapshot — хэши выбранных файлов, не копия и не ОС-песочница. Test ID и смысловая релевантность assertion остаются суждением агента/хоста.
- `delivery_complete` не означает соответствие. Разногласия показываются отдельно; финальное согласование выполняет хост. После изменения исходников нужен новый run.
- Статический HTML не отслеживает будущие изменения: перед решением обновляйте status/report.
- PHP SDK даёт syntax_only. Composer autoload и тесты — доверенный исполняемый код; оператор отвечает за изолированную среду. Инструмент не запускает тесты автоматически.

Одна поддерживаемая сборка — `./tool`. Host-прототип перенесён в неё; ранние Core/PHPStan-пробы в `prototypes/core` — историческое исследование, не второй контракт продукта. В `.local/research/` сохранены прежние эксперименты и приватные снимки; `.local/` и `bin/` исключены из Git. Клонирование не восстанавливает локальные исследования/отчёты.
