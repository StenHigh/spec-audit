# spec-audit

> Проверка связи между спецификацией, реализацией и утверждениями тестов.

Пока это два исследовательских прототипа, а не готовый продукт и не утверждённая спецификация. Они сохранены отдельно от бизнес-проекта, чтобы продолжить разработку инструмента по spec-first подходу.

## Что сохранено

| Часть | Назначение |
| --- | --- |
| [Host CLI](prototypes/host/tool/main.go) | YAML-конфиг, снимок состава и хэшей файлов, задания mapper/redteam, проверка ответов и цитат, retry, JSON и HTML |
| [Skill-лаунчер](prototypes/host/skill/spec-host-pilot/SKILL.md) | Существующая AI-сессия распределяет проверки между независимыми агентами; автоматически не устанавливается |
| [Протокол агента](prototypes/host/skill/spec-host-pilot/references/protocol.txt) | Правила сопоставления требований, кода и утверждений тестов |
| [Core/SDK](prototypes/core/main.go) | Разбор Markdown через Goldmark, проверка схемы и происхождения PHP-фактов, Docker-мост и контрольные проверки |
| [PHPStan-проба](prototypes/core/PublicCallProbeRule.php) | Извлечение сведений о вызовах через публичный API PHPStan; отдельно от CLI |

Два Go-модуля намеренно не объединены: этот коммит сохраняет проверенные эксперименты, а не фиксирует архитектуру реализации.

## Проверка и сборка

Для разработки нужен Go 1.27.0 или новее; целевые ОС — macOS и Linux. Из корня репозитория:

```bash
go -C prototypes/host/tool test ./...
go -C prototypes/core test ./...
CGO_ENABLED=0 go -C prototypes/host/tool build -o ../../../bin/spec-host-pilot .
CGO_ENABLED=0 go -C prototypes/core build -o ../../bin/spec-core-pilot .
./bin/spec-core-pilot selfcheck
```

Проверки используют синтетические данные, без доступа к бизнес-проекту. Для готовых бинарников Go, Node и Python не нужны. PHP SDK требует уже работающий Docker Compose сервис `app` с проектом в `/var/www/html` и установленным `nikic/php-parser`; PHP на хосте не запускается. Сам Host CLI Docker не вызывает.

## Ограничения пилота

- Host CLI пока требует ровно два scope, `runtime: docker/app` и абсолютные пути. Формат конфига и проверяемый сценарий есть в [интеграционном тесте](prototypes/host/tool/main_test.go).
- `prepare` фиксирует состав и хэши источников, но не создаёт изолированную копию кода. Чистый снимок для независимых агентов подготавливает хост.
- `complete` означает получение ответов, не соответствие спецификации. Точные цитаты подтверждают источник, но не смысл утверждения и не выполнение теста.
- Смена абсолютных путей меняет `snapshot_id`: старые run нельзя продолжить после переноса простым редактированием конфига. Нужен новый run; исторические receipts не переписываются.
- Вызовов модельного API в Host CLI нет. HTTP-проверки в раннем Core — синтетический эксперимент, не решение встраивать AI в бинарник.

## Локальные материалы

В рабочей копии владельца `.local/research/` хранит исходные каталоги экспериментов, отчёты и снимки бизнес-кода. Они исключены из Git и не отправляются на GitHub. Клонирование репозитория их не восстанавливает; это локальное сохранение, не удалённая резервная копия. Кэши зависимостей и сборки не архивируются.

Следующий шаг — отдельная спецификация инструмента и отдельная спецификация его применения к бизнес-проекту. Go подходит по результатам пилотов; состав библиотек, контракт доказательств и полнота требований ещё не зафиксированы нормативно.
