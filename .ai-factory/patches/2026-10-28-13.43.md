# Владение reports_dir и распознавание корневых metadata

**Дата:** 2026-10-28 13:43 Europe/Minsk
**Файлы:** tool/audit_roots.go, tool/bundle.go, tool/publish.go, tool/discovery_ownership_test.go
**Серьёзность:** medium

## Проблема

Вложенный reports_dir мог совпасть с настоящим run родителя и скрыть полное сохранённое решение.
Автопоиск отклонял посторонние manifest/state в корне хранилища, хотя явные CONFIG публиковали его правильно.

## Причина

Исключение дочерних хранилищ назначало владельца только по пути, без проверки признаков родительского run.
Автопоиск принимал решение о спорных metadata до обнаружения полных областей.
Проверка только существующего manifest пропускала повреждённый run после удаления этого файла.

## Решение

Общий nestedReportPaths проверяет признаки сохранённого run перед назначением вложенной границы.
Publish, export и cleanup используют одну проверку и отказывают до изменения данных.
`savedRunEvidence` различает признаки аудита и посторонние metadata; она не подтверждает корректность аудита.
State, опись источников и журнал версий сохраняют отказ при потерянном manifest.
Автопоиск откладывает спорные manifest/state до обнаружения хранилищ.
Допуск возможен только у точного корня подтверждённого reports_dir без признаков аудита.
Ошибки чтения и симлинки остаются отказом.
Historical reader по-прежнему читает только выбранный run.
Диагностика использует существующий slog.Debug с префиксом [FIX:audit-roots].
