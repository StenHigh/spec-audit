# Точные raw-байты решения и общий лимит плана очистки

**Дата:** 2026-10-28 00:20 UTC
**Файлы:** tool/publish.go, tool/cleanup.go, tool/cleanup_publications.go, tool/publication_regression_test.go, tool/cleanup_publications_regression_test.go
**Серьёзность:** high

## Проблема

Публикация принимала прежний независимый receipt после изменения форматирования raw-решения.
Генератор выдавал допустимый крупный PLAN, который verify/apply не могли прочитать.

## Причина

Reader сравнивал parsed Latest, но брал hash решения из кэшированного report.History.
Равенство содержания не доказывает равенство точных raw-байтов.
Полная live-опись и дублированные metadata публикаций увеличивают PLAN относительно отдельного manifest.
Генератор не проверял размер, а schema dispatch и внутренний reader использовали лимит state 32 MiB.

## Решение

Latest и History отчёта сверяются со свежей summary сохранённого журнала.
Receipt и отображение используют свежую summary; observation задаёт State позднее.
PLAN schema 1/2 использует общий лимит 256 MiB при генерации и чтении.
Генератор проверяет точный CLI JSON с отступами, escaping и конечным LF.
Ошибки планирования возвращают nil, чтобы CLI не печатал пустой PLAN как частичный результат.
Schema, canonical ID и лимиты PROOF/manifest не меняются.
Debug-диагностика использует [FIX:publication] и [FIX:cleanup-plan].

```text
raw -> summary -> сравнение истории -> receipt -> публикация
PLAN -> ограниченный CLI JSON -> verify -> apply -> повтор
```

## Проверка и предотвращение

Две постоянные регрессии упали до исправления за 5.294s.
Первый адресный запуск после исправления прошёл за 48.218s.
Точное решение проверяется в latest и --run, включая безвредное форматирование внешнего журнала.
Крупный PLAN занимает 49 941 150 байт и моделирует уже удалённые 40 001 кандидата.
Публичные verify/apply/repeat проверяют реальный сохранённый аудит без создания 40 000 лишних файлов.
Прежняя физическая матрица проверяет удаление, прерывания, зависимости и блокировки.
Размер producer нужно сверять с reader в фактическом CLI формате, а не только в компактном JSON.
Hash свидетельства следует выводить из проверенного первичного журнала.
Итоговый полный Go-набор прошёл за 432.343s; vet/build прошли.
Повторное ревью завершилось без новых замечаний.
Подробные результаты и ограничения записаны в существующий план change.
