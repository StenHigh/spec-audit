# Границы OUT при автопоиске и независимый historical

**Дата:** 2026-10-28 00:45 Europe/Berlin
**Файлы:** tool/publish.go, tool/publication_regression_test.go, docs/tool-spec.md, docs/external-input.md
**Серьёзность:** high

## Проблема

Автопоиск без CONFIG разрешал OUT внутри выбранных источников.
Публикация добавляла собственные файлы в следующий snapshot и порождала новые дубли.
Historical A зависел от manifests и журналов версий всех соседних run.
Повреждённый B блокировал публикацию исправного A.

## Причина

Один Config одновременно задавал наблюдение источников и границы записи.
Подстановка ._unavailable отключала чтение checkout, но также снимала настоящие границы OUT.
Фильтр run применялся после полного чтения metadata хранилища.

## Решение

Общий guard проверяет рабочий CONFIG и сохранённые source boundaries до mkdir/staging.
Default учитывает все сохранённые run; historical учитывает только выбранный run.
Saved пути ограничивают запись без чтения старого checkout.
Прямой reader выбранного ID сохраняет прежнюю строгую проверку metadata и путей.
Default, discovery и cleanup по-прежнему проверяют все run.
Debug-диагностика использует [FIX:publication].

```text
CONFIG + сохранённые CONFIG -> границы OUT -> staging
--run A -> metadata A -> проверка A -> публикация A
```

Исторический тест отдельно повреждает manifest и журнал версий B, затем проверяет отказ при таком повреждении внутри A.
