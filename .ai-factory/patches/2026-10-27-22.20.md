# Выбор сохранённого аудита и границы публикации

**Дата:** 2026-10-27 22:20 UTC
**Файлы:** tool/publish.go, tool/overview.go, tool/corpus.html, tool/publication_regression_test.go, tool/publication_test.go, tool/external_test.go
**Серьёзность:** medium

## Проблема

Новый run без независимой проверки блокировал публикацию прежнего полного аудита.
Автопоиск пропускал допустимые reports_dir с именами results, artifacts, sources и dispatch.
Локальный archive-сайт получил непредусмотренный запрет OUT внутри проекта.

## Причина

Reader объединял отсутствие проверки и повреждение свидетельств одним условием отказа.
Поиск определял служебную роль каталога только по его имени.
Проверка OUT распространила ограничение external/citations на локальный archive-режим.
Прежние тесты проверяли pending до решения хоста, но пропускали ожидание независимой проверки.

## Решение

Валидная незавершённая проверка оставляет run вне списка пригодных результатов.
Default сохраняет прежний полный аудит; явный исторический выбор незавершённого run отказывает.
Карта отдельно показывает причину ожидания через latest.publication_pending.
Повреждённый журнал, потерянный receipt и несоответствие отчёту сохраняют отказ.

Поиск распознаёт run до обхода ресурсов и затем пропускает его содержимое.
Обычные имена каталогов остаются допустимыми; reports_dir должен находиться внутри AUDIT_ROOT.
Локальный archive-режим разрешает OUT внутри проекта вне выбранных путей источников и reports_dir.
Границы external/citations сохраняются. Debug-журнал использует префикс [FIX:publication].

```text
отчёт + журналы -> pending / пригодный run / повреждение
                         |          |
                    прежний run   выбранный run -> сайт

backup + live-опись -> proof -> удаление manifests -> удаление objects
                                                      |
                                              повтор тем же планом
```

## Проверка и предотвращение

Три постоянные регрессии воспроизвели ошибки до исправления: адресный запуск завершился с тремя отказами за 10.255s.
После исправления те же сценарии и связанные проверки прошли за 50.551s.
Матрица очистки с проверками блокировок прошла отдельно за 54.926s.
Она перебирает все пять префиксов удаления двух manifests и двух objects в двух хранилищах.
Каждый префикс проверяет повтор apply, hashes/modes сохранённого аудита и целостность невыбранных публикаций.
Default и historical генерируются после очистки, включая более новый run без независимой проверки.

При ревью нужно проверять переходы между этапами аудита и отличать незавершённость от повреждения.
Служебную роль каталога нужно определять по контексту, а ограничения записи — по режиму хранения.
Файлы go:embed нужно зафиксировать до запуска полного набора: TestSkillFiles сравнивает встроенные bytes с файлами на диске.
Финальный полный Go-набор прошёл за 402.442s после фиксации документов.
Полная повторная квалификация записана в существующем плане change.
