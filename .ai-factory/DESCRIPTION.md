# spec-audit

## Назначение

Самостоятельный инструмент аудита Markdown-спецификаций по коду и assertions тестов. Он помогает человеку находить дефекты, слабые проверки и неоднозначные требования, а не выдаёт сертификат соответствия. Проект развивается spec-first; нормативный источник — [спецификация инструмента](../docs/tool-spec.md).

Существующая AI-сессия выполняет смысловой анализ через независимые роли и согласование хоста. Go-бинарник индексирует источники, проверяет входные данные и происхождение свидетельств, хранит результаты и строит автономный JSON/HTML-отчёт. В бинарнике нет модельных API и ключей.

Инструмент универсальный; сведения конкретного проверяемого проекта приходят из его CONFIG и спецификаций. SMSPlace — текущий пилот, описанный [отдельно](../docs/smsplace-adoption.md), не источник defaults ядра. Аудит не исправляет бизнес-код и не управляет задачами трекера.

## Стек

- Go 1.27.0, стандартная библиотека, Goldmark для Markdown и `go.yaml.in/yaml/v3` для YAML; точные версии — [go.mod](../go.mod).
- Локальный CLI для macOS/Linux; файловое состояние, без сервера и базы данных.
- HTML/CSS/JavaScript встроены в бинарник; отчёту не нужны сеть и сервер.
- PHP — только проектный SDK в проверенном Docker-контейнере. Сейчас `syntax_only`; PHPStan/Larastan — следующий этап, не готовая интеграция.
- AI Factory — локальное средство разработки. Node нужен его установщику/отдельным helper-командам, но не готовому spec-audit. Необязательный UI dev-check использует отдельно установленный Playwright/Chromium.

## Архитектура

Однопакетный Go CLI с разделением ответственности по файлам и явной границей внешнего runtime. Фактическое устройство и направление развития — [ARCHITECTURE.md](ARCHITECTURE.md); это не предписание перевести код в многоуровневый framework.

## Команды разработки

Из корня spec-audit на хосте:

```sh
go test ./tool
go vet ./tool
CGO_ENABLED=0 go build -o bin/spec-audit ./tool
```

Синтетические Go-тесты не требуют пилота. PHP и проектные тесты — только с отдельным разрешением; PHP без host fallback. UI-check и примеры CLI — в [README](../README.md#сборка-и-проверки).

Текущее состояние — [README](../README.md#состояние-и-следующие-шаги), порядок развития — [ROADMAP.md](ROADMAP.md), обязательные ограничения — [RULES.md](RULES.md). Полнота всего корпуса, общая точность и экономия ещё не доказаны.
