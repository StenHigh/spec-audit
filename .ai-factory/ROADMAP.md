# Развитие spec-audit

Обновлено: 2026-09-16 (чистая сессия: пилот и синтетический проект). Это единственная очередь развития; подробные требования — в [спецификации инструмента](../docs/tool-spec.md). Флажок означает завершение названного ограниченного этапа, а не доказанную полноту всего продукта. Проверенные результаты и ограничения — в [README](../README.md#приёмка-и-ограничения).

## Завершённая основа

- [x] Ограниченный цикл аудита: Go CLI, declared/accepted-индекс, независимые роли, raw, согласование хоста и синтетические контроли. Самоприменение проверено на собственной спецификации; accepted ограничен 64 активными требованиями.
- [x] Автономная карта одного run: навигация ТЗ–код–assertions, различение наличия и достаточности тестов, графики по файлам ТЗ, темы и ссылки в редакторы. HTML принят владельцем; это ещё не обзор всего корпуса по заголовкам.
- [x] Самодостаточный контекст разработки: общие AGENTS/CLAUDE, локальный AI Factory для Codex/Claude, конфиг, правила и очередь. Не зависит от доступа к пилотному репозиторию или памяти прежней сессии.

## Ближайшие этапы — в этом порядке

- [x] **PHP/Laravel SDK с PHPStan/Larastan (п.1–3 §17.2).** [Контракт `sdk/3`](../docs/php-sdk-contract.md), команда `php-typed`, экспортёр в проверенном контейнере, fail-fast изоляция bootstrap, записи в state, подсказки в TaskBatch/HTML; приёмка SA-031…034 на синтетических примерах `acceptance/php-sdk/`. Порядок п.2 изменён решением владельца 2026-09-16: пилот — отладка, синтетика — приёмка. Известное ограничение: `app(Contract::class)` разрешается Larastan в привязку.
- [x] **Сравнение аудита с SDK и без него на пилоте (§17.2 п.4).** Выполнено 2026-09-16 по разрешению владельца: один accepted-раздел (8 норм), два run с fresh-context ролями, эталон связей до run B. Результат нейтральный: 12/16 против 10/16 опорных мест кода, 8/8 тестов в обоих, 0 ложных findings, время и токены сопоставимы, один случай завышения assertion с подсказками. Доказанного улучшения нет; повторные сравнения — по потребности, не в очереди.
- [x] **Поставка: подписанный релиз и установка skill (§18).** Объединяет прежние пункты «Безопасная установка audit-skill при init» и «Воспроизводимый выпуск macOS/Linux»; решение владельца 2026-09-16: `init` не меняется, skill ставится отдельной явной командой `skill install|update` (`--host` обязателен, `--replace` только для symlink/чужой ссылки/drift, чужое не удаляется). Релиз `v0.1.0`: `install.sh` + `release-manifest.json` с sha256, `update` с проверкой Ed25519, матрица только `darwin/arm64` + `linux/amd64` с нативной квалификацией в workflow; пилот переведён с symlink на встроенную копию. Linux исполнялся только на runner.
- [x] **Рабочий цикл из чистой AI-сессии.** Выполнено 2026-09-16 двумя новыми сессиями Claude Code через установленный launcher, без прежней памяти и встроенных путей: пилот, scope `02-finance` (reconcile 49 accept / 2 defer, обе роли с первой попытки, host review current, бизнес-код не тронут) и независимый синтетический проект `spec-audit-synthetic` (declared-профиль, 5 норм, авторизованный `test` с receipt `passed`/4 теста; host review совпал с независимыми ожиданиями `acceptance/expected.json` по 13 из 15 полей — расхождения только в assertion REQ-DEMO-004 `unknown` вместо `missing` и REQ-DEMO-005 `weak` вместо `unknown`, роли совпали между собой по 4 из 5 норм). Свидетельства — [README](../README.md#приёмка-и-ограничения), [документ применения](../docs/smsplace-adoption.md#чистая-ai-сессия-2026-09-16); ограничения Codex-сессии не проверялись (обе сессии — Claude Code).
- [ ] **Уроки чистой сессии (решение владельца по каждому пункту).** Из прогона 2026-09-16: версия бинарника не фиксируется в manifest/state (провенанс смешанного run не восстановить); reference-only файлы ТЗ нельзя включить в source_set без учёта в лимите 64 кандидатов; `protocol.txt` предписывает Codex-специфичный `apply_patch`, а результат mapper (354 КБ цитат) не помещался в один Write; при `scopes: []` одна роль получает все нормы × все файлы (~30 мин, ~0,5–0,6 M токенов) без рекомендации по разбиению; `reconcile` отдаёт `freshness: null` сразу после apply и прячет revision/clarity внутри accepted; локальный валидатор формы ответа роли пришлось писать вручную — кандидат на команду `validate` без записи в state. Это очередь на решение, не разрешение на реализацию.

## После ближайших этапов

- [ ] **Несколько разделов и обзор корпуса.** Контракт полноты инвентаря, настоящие разделы/заголовки ТЗ, сводная карта требований, реализации, известных GAP и достаточности assertions. Отдельно определить выявление противоречий норм и неописанного поведения; отсутствие связи не объявлять дефектом. Текущие показатели относятся к одному run и группируются по файлам.
- [ ] **Инкрементальная актуальность.** Обновлять затронутые требования, связи и проверки с сохранением происхождения и истории; не переносить старые «зелёные» выводы на изменённый код/ТЗ без основания.
- [ ] **Приёмка замены старого AI re-audit на пилоте.** По [спецификации применения](../docs/smsplace-adoption.md): список прежних гарантий и их замен, контрольный рабочий цикл, rollback. Старый CI временно сохраняется; текущая ограниченная обкатка не является разрешением удалить прежний инструмент.
- [ ] **Пробное преобразование бизнес-ТЗ.** Отдельная спецификация применения, один пробный раздел, сравнение обязанностей до/после. Не смешивать с универсальным ядром или считать автоматически выполненным после SDK; подготовка к ISO не равна соответствию ISO.

## Исследования, не разрешение на реализацию

`php-typed` остаётся опцией по требованию: решение владельца 2026-09-16 после нейтрального сравнения. Повторное сравнение — только на scope с интерфейсами/биндингами/фасадами, где роли без SDK дают `unknown`; до такого scope в SDK не вкладываться. Notes/compact остаются test-only: рабочая интеграция не принята. Уменьшение JSON не доказывает экономию токенов/денег и сохранение качества; нужен сопоставимый контроль с явными критериями перехода. Новые языки и фреймворки добавляются по конкретной потребности. Graphify/graph/cache, автоматические задачи трекера и модельный API в бинарнике не входят в ближайшую работу.

Ошибки извлечения обязанностей, применимости требований и достаточности assertions продолжаем превращать в независимые регрессии. Инструмент развивается spec-first и проверяется на собственной спецификации, а не только на пилоте.
