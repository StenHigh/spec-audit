# Развитие spec-audit

Обновлено: 2026-09-16 (вечер). Это единственная очередь развития; подробные требования — в [спецификации инструмента](../docs/tool-spec.md). Флажок означает завершение названного ограниченного этапа, а не доказанную полноту всего продукта. Проверенные результаты и ограничения — в [README](../README.md#приёмка-и-ограничения).

## Завершённая основа

- [x] Ограниченный цикл аудита: Go CLI, declared/accepted-индекс, независимые роли, raw, согласование хоста и синтетические контроли. Самоприменение проверено на собственной спецификации; accepted ограничен 64 активными требованиями.
- [x] Автономная карта одного run: навигация ТЗ–код–assertions, различение наличия и достаточности тестов, графики по файлам ТЗ, темы и ссылки в редакторы. HTML принят владельцем; это ещё не обзор всего корпуса по заголовкам.
- [x] Самодостаточный контекст разработки: общие AGENTS/CLAUDE, локальный AI Factory для Codex/Claude, конфиг, правила и очередь. Не зависит от доступа к пилотному репозиторию или памяти прежней сессии.

## Ближайшие этапы — в этом порядке

- [x] **PHP/Laravel SDK с PHPStan/Larastan (п.1–3 §17.2).** [Контракт `sdk/3`](../docs/php-sdk-contract.md), команда `php-typed`, экспортёр в проверенном контейнере, fail-fast изоляция bootstrap, записи в state, подсказки в TaskBatch/HTML; приёмка SA-031…034 на синтетических примерах `acceptance/php-sdk/`. Порядок п.2 изменён решением владельца 2026-09-16: пилот — отладка, синтетика — приёмка. Известное ограничение: `app(Contract::class)` разрешается Larastan в привязку.
- [x] **Сравнение аудита с SDK и без него на пилоте (§17.2 п.4).** Выполнено 2026-09-16 по разрешению владельца: один accepted-раздел (8 норм), два run с fresh-context ролями, эталон связей до run B. Результат нейтральный: 12/16 против 10/16 опорных мест кода, 8/8 тестов в обоих, 0 ложных findings, время и токены сопоставимы, один случай завышения assertion с подсказками. Доказанного улучшения нет; повторные сравнения — по потребности, не в очереди.
- [ ] **Безопасная установка audit-skill при init.** Явный выбор владельца, конфликты и сохранение чужих настроек, обновление без дублей; переносимая поставка без ссылки на checkout инструмента. Сейчас `init` создаёт только YAML; локальная установка пилота ручная. Это не установка AI Factory в проверяемый проект.
- [ ] **Рабочий цикл из чистой AI-сессии.** Пройти через установленный launcher один ограниченный раздел пилота и независимый синтетический проект, без прежней памяти и встроенных путей. Зафиксировать фактические ограничения Codex/Claude, не менять бизнес-код и задачи.
- [ ] **Воспроизводимый выпуск macOS/Linux.** Сборка, установка/обновление в `~/.local/bin` без языкового runtime для детерминированных команд; отдельное подтверждение исполнения каждой заявленной платформы. Cross-build сам по себе недостаточен.

## После ближайших этапов

- [ ] **Несколько разделов и обзор корпуса.** Контракт полноты инвентаря, настоящие разделы/заголовки ТЗ, сводная карта требований, реализации, известных GAP и достаточности assertions. Отдельно определить выявление противоречий норм и неописанного поведения; отсутствие связи не объявлять дефектом. Текущие показатели относятся к одному run и группируются по файлам.
- [ ] **Инкрементальная актуальность.** Обновлять затронутые требования, связи и проверки с сохранением происхождения и истории; не переносить старые «зелёные» выводы на изменённый код/ТЗ без основания.
- [ ] **Приёмка замены старого AI re-audit на пилоте.** По [спецификации применения](../docs/smsplace-adoption.md): список прежних гарантий и их замен, контрольный рабочий цикл, rollback. Старый CI временно сохраняется; текущая ограниченная обкатка не является разрешением удалить прежний инструмент.
- [ ] **Пробное преобразование бизнес-ТЗ.** Отдельная спецификация применения, один пробный раздел, сравнение обязанностей до/после. Не смешивать с универсальным ядром или считать автоматически выполненным после SDK; подготовка к ISO не равна соответствию ISO.

## Исследования, не разрешение на реализацию

Notes/compact остаются test-only: рабочая интеграция не принята. Уменьшение JSON не доказывает экономию токенов/денег и сохранение качества; нужен сопоставимый контроль с явными критериями перехода. Новые языки и фреймворки добавляются по конкретной потребности. Graphify/graph/cache, автоматические задачи трекера и модельный API в бинарнике не входят в ближайшую работу.

Ошибки извлечения обязанностей, применимости требований и достаточности assertions продолжаем превращать в независимые регрессии. Инструмент развивается spec-first и проверяется на собственной спецификации, а не только на пилоте.
