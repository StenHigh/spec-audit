# Соглашения разработки

## Код и границы

- Поддерживаемая реализация — `tool/`, один Go `package main`; `prototypes/` — исследовательская история. Новую логику помещай рядом с существующей ответственностью из [ARCHITECTURE.md](../ARCHITECTURE.md), не создавай параллельное ядро.
- Go: `gofmt`, существующие имена типов/функций и явные ошибки. JSON/YAML-поля — по контракту, не переименовывай ради стиля. Используй стандартную библиотеку и существующие helpers прежде новой зависимости.
- Сохраняй ранние проверки, лимиты входов, контроль путей/симлинков и snapshot/hash. Ошибку возвращай с контекстом; не прячь неизвестность успешным fallback. Для CLI stdout — JSON, диагностика — stderr через существующий `slog`/`LOG_LEVEL`.
- Запись состояния — через общий `atomicWrite`, запуск процессов — через существующий runtime с timeout и receipt. Не ослабляй проверки ради удобства SDK или HTML.
- PHP-факты сейчас синтаксические. Типизированный SDK, Task/HTML-потребители и bootstrap-boundary проектируются по [§17](../../docs/tool-spec.md#17-php-и-laravel-sdk), а не выдаются за уже работающие.
- UI остаётся автономным и безопасным для недоверенных цитат: экранирование, allowlist URI-профилей, доступность без JavaScript. Данные браузерных настроек не меняют исходники или CONFIG.

## Проверки

- Для исправления сначала воспроизведение, затем адресная синтетическая регрессия рядом с кодом в `tool/*_test.go`. Проверь общий helper и его затронутых потребителей, не только один путь ошибки.
- Перед завершением изменений Go: `go test ./tool`, `go vet ./tool`, сборка; для HTML также UI-check из [README](../../README.md#первый-запуск), если среда уже доступна. Не устанавливай dev-среду молча.
- В отчёте назови среду, реально выполненные проверки и пропуски. Обычный Go test не заменяет независимую смысловую приёмку; тест с отсутствующими внешними входами может быть skipped.

## Контекст агента

- Ответы и новые проектные документы — по-русски, технические термины сохраняются. Имена форматов, API и файлов не переводятся.
- Общие инструкции AI Factory лежат локально в `.agents/skills` и `.claude/skills`; не обращайся за ними к другому проекту. Не загружай все skills, прототипы и историю по умолчанию.
- `CLAUDE.md` остаётся симлинком на корневой `AGENTS.md`. Правь целевой файл, не создавай второй расходящийся handoff.
- Не добавляй plugin framework, граф, cache или новый SDK без проверенной потребности. Общие продуктовые границы — в [RULES.md](../RULES.md), очередь — в [ROADMAP.md](../ROADMAP.md).
